Top systemic issues

  1. Undocumented per-session provisional-credit cap (Blockers 039, 040, 041). The written rule (doc_(general)_015 criterion 4) is a 12-month history gate, but the gold trajectories treat it as a per-session cap with inconsistent limits (3 in 039, ~2 in 041). With ≤1 prior dispute the literal rule leaves every eligible dispute eligible, so a correct agent marks more than gold and fails. The cap is nowhere documented.
  2. Reward rounding undocumented AND inconsistent (Majors 017, 018, 019, 021, 022, 029; round-seed Minors 020, 026, 027). rewards_earned is stored rounded with no documented rule, and the convention differs across tasks (floor vs round-half-up, verified by recomputation). Genuine errors are gross and separable from ±1 noise, so disputing only "material" discrepancies recovers each set — Major, not Blocker. task_028 alone ships the floor-policy doc and is clean.
  3. APY "relationship bonus" stacking is self-contradictory (Majors 095, 097). The +0.025% bonus is labelled both a "relationship bonus" (stacks) and a "credit-card APY bonus" (highest-only); task_093 includes it while task_097 omits it for the identical scenario, so the exact expected_apy/credit DB write is non-deterministic.
  4. DB-keyed product selection is non-unique (Blockers 063, 075; Major 102). The chosen product is part of the DB key, so it must be the unique optimum, but task_063 has two cards with identical +0.15% bonuses, task_075 two checking accounts both $0 foreign-ATM, and task_102's docs contain a strictly-higher-bonus alternative than the gold.
  5. Same-date duplicate-charge ties (Blockers 083, 084). Two identical charges share a date with no timestamp, so "dispute the earliest (first)" has no deterministic referent; the gold disputes the second. (task_083 also: its ACTION gold omits the required customer_max_liability_amount.)
  6. Gold-trajectory construction bugs (Blockers 074, 082, 101). task_082 omits a required cancel-and-reissue; task_101 caps referrals at 2 with no basis (the 9-day window counts received bonuses and the user has none); task_074's credits require counting transactions dated after the fixed clock plus an undocumented fee baseline.
  7. Incomplete required_documents annotations — NOT defects under the full-KB-read model (050, 088, 096). Each omits a doc the gold uses, but every one exists in the KB and is findable, so the agent can still solve the task. Worth fixing the annotations, but not solvability defects here.
  8. Pervasive but cosmetic $-on-non-currency corruption (25/698 docs). Credit scores as "$720", "$105 days", EcoCard "$5.00 points". Rarely load-bearing → Minor.

Methodology & grading model

  • Grading. ~88 tasks grade on final-DB exact match (gold actions replayed → reference DB; the verified scorer only allows extra discoverable-tool reads and strips closure_reason); ~9 grade on ACTION match. So for DB tasks every DB-writing gold argument must be uniquely derivable.
